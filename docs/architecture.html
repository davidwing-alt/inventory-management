Overview

System Architecture

The system is a classic two-tier SPA + API split. The browser runs a Vue 3 single-page app that calls a FastAPI backend over HTTP/JSON. The backend holds all state in memory, hydrated once at startup from flat JSON files.

Request Lifecycle

Data Flow

A single example — the user changes a filter on the Dashboard — traced end to end. The filter bar is the central coordination point: every view watches shared filter state and reloads its data when it changes.

User changes a filter
FilterBar.vue binds four dropdowns — Period, Warehouse, Category, Status — via v-model.
Shared state updates
The selection mutates a ref in the useFilters() composable (a singleton), so all views see the change.
View reacts
A watch() in the active view fires and calls the relevant API method with getCurrentFilters().
api.js builds the request
api.js serializes active filters into URLSearchParams (skipping 'all') and issues an axios GET to http://localhost:8001/api/….
FastAPI filters in memory
The route applies apply_filters() (warehouse / category / status) and filter_by_month() (month or Q1–Q4) over the in-memory lists, then aggregates KPIs.
Pydantic validates & serializes
Response models enforce shape and types, returning clean JSON.
View stores raw data
The payload lands in refs (e.g. allOrders, inventoryItems).
Computed properties derive the UI
Cached computed() values shape charts and tables; the template re-renders. Currency and labels pass through useI18n().

The filter system

Four filters drive the entire app through shared query params. Endpoints honor only the filters that apply to their data — e.g. inventory has no time dimension, so it ignores Period and Status.

API Surface

All endpoints are namespaced under /api. Reads dominate; the few writes (tasks, purchase orders) mutate in-memory state only.
